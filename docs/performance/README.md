## 새 보고서를 쓸 때

파일 이름은 `YYYY-MM-DD-제목.md`. 아래를 반드시 적는다. 빠지면 나중에 결과를 믿을 수 없다.

1. **환경**: 장비, Docker VM 자원, 게이트웨이 커밋, litellm 이미지·버전, 자원 제한, 부하 생성기 버전
2. **조건**: 업스트림 응답 시간, 시나리오 목록과 지속 시간
3. **결과 요약**과 **전체 표**(`bench/compare.py <RUN_ID>` 출력). 원본 `bench/results/` 는 git 에서 제외되므로 표를 문서에 남긴다
4. **정합성 확인 결과**(요청 수 대 DB 기록 수). 한쪽만 DB 에 안 쓰면 비교가 무의미하다
5. **해석과 한계**: 반복 횟수, 비교 대상이 같은 단위인지, 자원 제한에 닿았는지, 아직 설명하지 못한 이상 현상
6. **다시 재는 방법**(명령어)

## 지켜야 할 것

- 절대 수치는 시험 장비 기준이다. 서로 다른 장비·날짜의 절대값을 직접 비교하지 않고, 같은 조건에서 대상끼리 견주는 **상대 비교**로 쓴다
- 세 대상은 **같은 `RUN_ID`**, 같은 자원 제한, 한 번에 하나씩 돌린다
- 돌리는 동안 시험 장비에서 다른 무거운 작업을 하지 않는다
- 이전 보고서의 "시험 도구에서 겪은 함정"을 먼저 읽는다(예: 가짜 업스트림 응답 `id` 가 고정이면 litellm 이 사용량 기록을 합친다)
- 한 번만 잰 결과로 작은 차이를 결론 내지 않는다. 필요하면 같은 조건을 여러 번 재서 중앙값을 쓴다
