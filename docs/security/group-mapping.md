# Keycloak 그룹 → 팀·관리자 매핑

Keycloak 그룹으로 팀 소속과 관리자 역할을 자동으로 정한다. **하나의 표**를 두 경로가 같이 쓴다.

| 경로 | 언제 적용하나 | 어디에 반영하나 |
|---|---|---|
| JWT 직접 호출(`docs/security/jwt-auth.md`) | 요청마다, 그 토큰의 그룹 | 그 요청의 팀·역할(DB 의 소속은 팀원으로 추가만) |
| SSO 로그인(대시보드·데스크탑) | **로그인할 때** | DB 의 팀원 기록과 사용자 역할 |

SSO 로그인으로 받은 로그인 키는 요청마다 사용자·팀 행을 읽으므로, 로그인 때 DB 를 맞춰 두면 그 키의 권한이 바로 달라진다.

## 설정

| 환경 변수 | 뜻 |
|---|---|
| `GATEWAY_GROUP_MAP` | 그룹 → 팀·관리자 표(JSON). 예: `{"eng":{"team_id":"research"},"gateway-admins":{"admin":true}}` |
| `GATEWAY_GROUPS_CLAIM` | 그룹 목록이 든 클레임. 기본 `groups`. 점으로 중첩 경로를 쓸 수 있다(`realm_access.roles`) |

표가 비어 있으면 그룹을 보지 않는다. 틀린 설정(깨진 JSON, 모르는 필드, 아무것도 주지 않는 그룹)은 기동을 멈춘다. JWT 호출에 처음 붙였던 `GATEWAY_JWT_GROUP_MAP`·`GATEWAY_JWT_GROUPS_CLAIM` 도 같은 뜻으로 읽는다. 새 이름과 옛 이름을 둘 다 적으면 어느 쪽인지 헷갈려 기동을 멈춘다. 표는 기동 때 읽으므로 바꾸려면 재기동한다.

### Keycloak 쪽 설정
- 클라이언트에 **Group Membership 매퍼**를 둔다. SSO 로그인은 로그인 응답(userinfo)에서 그룹을 읽으므로 **"Add to userinfo" 를 켠다**. JWT 호출은 액세스 토큰에 들어가야 하니 "Add to access token" 도 켠다. 그룹 이름 앞의 `/` 는 "Full group path" 를 끄면 없어진다. 표의 이름은 토큰·응답에 든 문자열과 똑같아야 한다.

## SSO 로그인 때 일어나는 일

표에 나오는 팀은 **"그룹이 기준"인 팀**이다. 로그인할 때마다 다음을 맞춘다.

| 항목 | 동작 |
|---|---|
| 팀 추가 | 사용자가 그 팀의 그룹에 있으면 팀원(role `user`)으로 넣는다 |
| 팀 제거 | 그룹이 없으면 팀원에서 뺀다. **그 사용자의 그 팀 키도 함께 지워진다**(관리자가 팀원을 손으로 뺄 때와 같다). 표에 없는 팀의 수동 소속은 건드리지 않는다 |
| 관리자 올림 | `admin: true` 인 그룹에 있고 관리자가 아니면 `proxy_admin` 으로 올린다. 올릴 때 원래 역할과 표시(사용자 metadata 의 `group_admin`)를 남긴다 |
| 관리자 내림 | 그룹을 떠났고 **그 표시가 있으면** 원래 역할로 되돌린다. 관리자가 손으로 지정한 관리자(표시 없음)는 그룹과 상관없이 유지한다 |
| 없는 팀 | 표가 가리키는 팀이 아직 없으면 건너뛰고 로그에 경고한다. 로그인은 막지 않는다(표 오타로 전원 로그인이 막히지 않게) |
| 그룹 클레임이 없는 응답 | **아무것도 바꾸지 않는다**(Keycloak 매퍼를 빼먹었을 때 전원이 팀에서 빠지는 사고를 막으려고. 로그에 경고). 클레임은 있는데 빈 목록이면 "어떤 그룹에도 없음"으로 보고 거둔다 |
| 감사 기록 | 바뀐 것이 있으면 `group_sync` 한 줄: 매칭된 그룹, 추가·제거한 팀, 관리자 올림/내림. 표에 없는 그룹 이름은 남기지 않는다 |

팀마다 따로 처리하는 단계들이고 하나의 트랜잭션은 아니다. 모두 같은 결과로 수렴하므로 중간에 멈추면 다음 로그인이 이어서 맞춘다.

## 한계

- **반영은 로그인 때다.** 로그인 키가 7일 유효해서, 그룹에서 빠진 사람은 다음 로그인까지(최대 7일) 이전 팀 권한이 남을 수 있다. 급하면 관리자가 그 사용자를 팀에서 빼거나 팀을 막는다(바로 반영된다). 즉시 취소가 필요하면 JWT 직접 호출(토큰 수명 5분)을 쓴다.
- 한 사용자가 여러 그룹에 속하면 여러 팀에 들어가고, 데스크탑은 로그인 때 팀을 고른다.
- 표를 바꾸면 재기동해야 하고, 이미 있는 팀원 기록은 해당 사용자가 다시 로그인할 때 맞춰진다.
- 관리자가 대시보드에서 "그룹이 기준"인 팀에 손으로 넣은 사람은, 그 그룹에 없으면 다음 로그인에 빠진다. 수동으로 관리할 팀은 표에 넣지 않는다.
